# I2C Master Simulation — Waveform Verification Guide

## Overview

This document describes what to look for in simulation waveforms when testing the I2C master TX and RX modules.

## Waveform Signal Groups

### 1. System Signals

**clk** (System Clock)
- 50 MHz square wave (20 ns period)
- Used to synchronize all logic
- Should be regular and consistent

**rst_n** (Active-Low Reset)
- '0' for first 200 ns
- Then '1' for normal operation
- All modules initialized on rising edge of rst_n

### 2. I2C Clock Signals

**scl** (Serial Clock Line)
- Square wave, frequency determined by PRESCALER
- With PRESCALER=50: ~500 kHz (2 μs period)
- Generated by i2c_master_clock module

**scl_rise** (SCL Rising Edge Strobe)
- Single clock pulse when SCL goes from '0' to '1'
- Used by RX module to sample data
- Used by TX module for timing

**scl_fall** (SCL Falling Edge Strobe)
- Single clock pulse when SCL goes from '1' to '0'
- Used by TX module to change data
- Used by slave simulator to prepare next bit

### 3. I2C Data Line

**sda_i2c_bus** (Serial Data Line - I2C Bus)
- Open-drain simulated line
- Wired-AND of TX output and slave output
- Should be clean '0' or '1' (never 'X')
- Changes only during SCL='0' periods (except START/STOP)

### 4. TX Module Signals

**tx_start** (TX Start Trigger)
- Pulse (1 clock cycle) to initiate transmission
- Should go '1' for exactly 1 clock period

**tx_busy** (TX Busy Status)
- '1' during transmission
- '0' when idle
- Duration = 9 SCL cycles (8 data + 1 ACK)

**tx_data_in** (TX Input Data)
- 8-bit value to transmit
- Should be stable while tx_busy='1'
- Transmitted MSB first

**tx_done** (TX Transmission Complete)
- Pulse after transmission finishes
- Indicates valid ACK was received
- Should be 1 clock cycle wide

**tx_ack_received** (ACK Status)
- '0' = slave acknowledged (ACK)
- '1' = slave sent NACK
- Valid after tx_done pulse

### 5. RX Module Signals

**rx_start** (RX Start Trigger)
- Pulse (1 clock cycle) to initiate reception
- Should go '1' for exactly 1 clock period

**rx_busy** (RX Busy Status)
- '1' during reception
- '0' when idle
- Duration = 8 SCL cycles (slave drives data)

**rx_data_out** (RX Output Data)
- Contains received byte
- Valid after rx_data_valid pulse
- Should match slave transmitted data

**rx_data_valid** (RX Data Valid Flag)
- Pulse indicating data reception complete
- Check rx_data_out value at this time
- Should be 1 clock cycle wide

### 6. Slave Simulator Signals

**slave_enabled** (Slave Active)
- '1' = slave is active
- '0' = slave inactive (bus released)

**slave_data** (Slave Data to Transmit)
- 8-bit value transmitted during RX tests
- Example: 0xAA = 10101010

**slave_sda_drive** (Slave SDA Control)
- '0' = slave driving SDA low
- '1' = slave releasing SDA (high-Z)
- Used in wired-AND to create sda_i2c_bus

## Expected Waveform Timeline

### TEST 1: TX Transmission of 0xA5 (10100101)

```
Time     Signal              Behavior
───────  ──────────────────  ──────────────────────────────
0.2μs    rst_n               Goes high (reset released)
0.5μs    tx_start            Pulses high
         tx_busy             Goes high
         tx_data_in          = 0xA5

0.5-1μs  scl                 Starts toggling
         sda_i2c_bus         Starts changing on scl_fall

1.0μs    sda_i2c_bus         First bit (1 from 0xA5)
         scl_fall            Strobe pulse

1.2μs    sda_i2c_bus         Changes (second bit = 0)
         scl_fall            Strobe pulse

1.4μs    sda_i2c_bus         Changes (third bit = 1)
         scl_fall            Strobe pulse

... continues for 8 bits ...

1.8μs    scl_rise            Strobe for 9th cycle (ACK)
         slave_sda_drive     Goes low (slave ACK)
         sda_i2c_bus         Goes low (wired-AND)

1.9μs    scl_fall            End of ACK cycle
         tx_busy             Goes low
         tx_done             Pulses high
         tx_ack_received     = '0' (ACK received)

2.0μs    Test 1 complete, ready for Test 2
```

### TEST 3: RX Reception of 0xAA (10101010)

```
Time     Signal              Behavior
───────  ──────────────────  ──────────────────────────────
3.5μs    rx_start            Pulses high
         rx_busy             Goes high
         slave_enabled       = '1'
         slave_data          = 0xAA

3.5-4.0μs scl                Starts toggling
         slave_sda_drive     Changes each scl_fall
         sda_i2c_bus         Follows slave_sda_drive

3.7μs    scl_rise            First sample strobe
         RX module           Captures bit 7 (1) from SDA
         
3.9μs    scl_fall
         slave_sda_drive     Changes (next bit = 0)

4.1μs    scl_rise            Second sample strobe
         RX module           Captures bit 6 (0) from SDA

... continues for 8 bits ...

4.4μs    scl_fall            After 8th bit
         rx_busy             Goes low
         rx_data_valid       Pulses high
         rx_data_out         = 0xAA (captured data)

4.5μs    Test 3 complete
```

## Verification Checklist

### Clock Synchronization
- [ ] CLK is regular 50 MHz square wave
- [ ] SCL is regular (period = 2 × PRESCALER × 20ns)
- [ ] scl_rise pulses occur only on SCL 0→1 transitions
- [ ] scl_fall pulses occur only on SCL 1→0 transitions

### Data Line Behavior (TX Test)
- [ ] sda_i2c_bus changes only during scl='0' or scl_fall
- [ ] Each bit corresponds to correct value (0xA5 = 10100101)
- [ ] Bits transmitted MSB first (bit 7 → bit 6 → ... → bit 0)
- [ ] After 8 bits, 9th SCL cycle for ACK phase
- [ ] During ACK: slave_sda_drive='0' pulls sda_i2c_bus low
- [ ] No glitches or metastability ('X' states) on SDA

### Data Line Behavior (RX Test)
- [ ] slave_sda_drive changes on each scl_fall
- [ ] sda_i2c_bus reflects slave_sda_drive changes
- [ ] Each bit held stable during scl_rise for sampling
- [ ] rx_data_out captures bits in correct order
- [ ] Final rx_data_out matches slave_data input

### Timing Constraints
- [ ] tx_busy high duration ≈ 9 SCL cycles
- [ ] rx_busy high duration ≈ 8 SCL cycles
- [ ] All strobes (start, done, data_valid) exactly 1 clock wide
- [ ] ACK phase occurs on 9th SCL cycle (not before)

### Signal Integrity
- [ ] No simultaneous TX and slave SDA drives (bus conflicts)
- [ ] No 'X', 'Z', or 'W' states (except in initial state)
- [ ] All transitions are synchronous to clk
- [ ] Proper reset initialization (all signals valid at 0.2μs)

## Waveform Zoom Tips

### To examine bit-level transitions:

1. In Vivado waveform viewer, select time range around data transition
2. Use zoom in/out buttons to see SCL and SDA alignment
3. Hover over sda_i2c_bus to see exact transition time
4. Verify SDA changes happen during scl='0' window

### To verify SCL timing:

1. Measure SCL period (low time + high time)
2. Should equal 2 × PRESCALER × 20ns = 2 × 50 × 20ns = 2000ns
3. Check SCL is exactly 50% duty cycle

### To verify ACK sampling:

1. Find 9th SCL cycle in TX test
2. Check scl_rise strobe during this cycle
3. Verify slave_sda_drive='0' at scl_rise time
4. Confirm sda_i2c_bus='0' through wired-AND

## Expected Signal Counts

For 10ms simulation with 5 tests:

**SCL Cycles:**
- TEST 1 (TX): 9 cycles (8 data + 1 ACK)
- TEST 2 (TX): 9 cycles (8 data + 1 ACK)
- TEST 3 (RX): 8 cycles (8 data, no ACK)
- TEST 4 (RX): 8 cycles (8 data, no ACK)
- TEST 5 (TX): 9 cycles (8 data + 1 ACK)
- **Total: 43 SCL cycles**

**SDA Transitions:**
- Should match transmitted data patterns
- Example TEST 1 (0xA5 = 10100101): transitions at bits where value changes
- Counting transitions verifies proper bit ordering

## Debugging Failed Tests

### If rx_data_out ≠ slave_data:

1. Check slave_sda_drive transitions occur on scl_fall
2. Verify sda_i2c_bus stable during scl_rise
3. Zoom in on RX sampling: scl_rise should occur when SDA is stable
4. Check rx_data_out bits are captured in order (bit 7 first)

### If tx_ack_received ≠ 0 (no ACK):

1. Check slave_sda_drive='0' during 9th SCL high period
2. Verify sda_i2c_bus='0' (wired-AND working)
3. Check TX module scl_rise strobe fires during 9th cycle
4. Ensure slave simulator is enabled (slave_enabled='1')

### If tx_busy stays high too long:

1. Count SCL cycles (should be 9)
2. Check if SCL frequency is correct (adjust PRESCALER if needed)
3. Verify scl_fall strobes are firing correctly
4. Check TX FSM state progression (add TX state signal to waveform)

## Signal Relationships

**Critical timing relationships:**

1. **Data Valid During SCL High:**
   - SDA changes only during scl='0'
   - SDA stable during scl='1'

2. **ACK Timing:**
   - 9th SCL cycle after 8 data bits
   - Slave pulls SDA low during 9th cycle high period
   - Master samples ACK on scl_rise of 9th cycle

3. **Clock Synchronization:**
   - All state changes synchronized to clk rising edge
   - strobes (scl_rise, scl_fall) span exactly 1 clk period
   - Data changes on following clk rising edge after strobe

## Performance Metrics

**Expected simulation performance:**

- **Elaboration time:** <5 seconds
- **Simulation speed:** ~100k clk cycles/second (0.02 real-time speed)
- **Total simulation time:** 10 ms = 500k clk cycles ≈ 5 seconds

If simulation is much slower, check for:
- Excessive processes with long delays
- Very large arrays or wide signals
- Uninitialized signals causing 'X' propagation
